# Social Network — Independent Project 1

A runnable, mobile-friendly social networking starter with its own frontend and HTTP API. It is inspired by familiar social-networking patterns but uses original branding and assets. It is not affiliated with or endorsed by Facebook/Meta.

## Included

- Responsive feed and post composer (text posts and image URLs)
- Registration, sign-in, sign-out, session cookie and password hashing
- Profiles and profile editing
- Reactions and comments
- Friend requests and friend list
- Groups: browse, create, join
- Direct-message conversations
- Notifications generated by social actions
- Search across people, posts and groups
- Persistent local JSON data store, seeded demo content, and API tests
- No third-party runtime dependencies

## Requirements

Node.js 20 or later.

## Run locally

```bash
cp .env.example .env
npm start
```

Open http://localhost:3000. The application initializes `data/db.json` on first run. A demo account is seeded:

- Email: `demo@example.com`
- Password: `DemoPass123!`

Change the demo password and set a long random `SESSION_SECRET` before exposing this app to a network. Demo data is for local evaluation only.

## Test

```bash
npm test
```

## API overview

All API endpoints are prefixed by `/api`.

- `GET /api/health`
- `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`
- `GET /api/feed`, `POST /api/posts`
- `POST /api/posts/:id/reactions`, `POST /api/posts/:id/comments`
- `GET /api/users`, `GET /api/users/:id`, `PATCH /api/users/me`
- `POST /api/friends/:id/request`, `POST /api/friends/:id/accept`
- `GET /api/groups`, `POST /api/groups`, `POST /api/groups/:id/join`
- `GET /api/messages`, `POST /api/messages`
- `GET /api/notifications`, `GET /api/search?q=...`

## Important production hardening

This is a working starter, not a production-scale Facebook replacement. Before public launch, replace the JSON store with PostgreSQL or another transactional database; add database migrations, email verification, password reset, CSRF protection, rate limiting, moderation/reporting, upload storage and validation, observability, backups, security review, privacy/legal pages, and production session storage. The built-in JSON store is intended for single-process development and is not safe for multi-instance deployment. Image posts currently accept URLs rather than uploading files. Messaging and friend/group features are intentionally foundational and need additional product work for large-scale use.

## Repository separation

This folder is a standalone project. It does not connect to, import, or modify any existing Creator Hub repository, database, or deployment.
