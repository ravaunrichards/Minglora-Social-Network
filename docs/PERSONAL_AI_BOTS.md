# Minglora Personal AI Bots Network — Implementation Tracker

**Complete recommendation specification:** [PERSONAL_AI_BOT_NETWORK_RECOMMENDATIONS.md](PERSONAL_AI_BOT_NETWORK_RECOMMENDATIONS.md)

This tracker records the verified implementation state of the existing feature branch. The specification describes the ten recommended systems and their acceptance criteria; it does not claim that unfinished systems are operational. Production migrations, provider inference, scheduler deployment and autonomous execution remain gated.

## Still not implemented

|---|---|

The Admin Centre canonical identity table loads 100 rows at a time using a validated owner-only `/identities` endpoint with `nextOffset`/`hasMore` and append-only page loading. Owner-only identity batch history also pages through the runtime-state collection (50 per page), filtering by owner before offset/limit. Not production-deployed or live-verified. Bot task/team/settings state still uses the existing JSONB compatibility adapter. |

Department, vacancy, application, appointment and history data use the runtime-state compatibility adapter only; normalized HR tables/RPCs, browser/device acceptance, role permissions, governance execution and full employee lifecycle remain unfinished. |
| Durable PostgreSQL task queue, lease/retry RPCs and worker core | Owner task-list API and Admin Centre page through durable task records (100 per page). The draft-only worker is limited to four approved, low-impact text task types, renews its lease throughout provider generation, aborts/rejects results on lease loss, and reports failure-write rejection as `failure_unrecorded`. The focused worker suite contains 16 cases and passed 16/16 locally on Node 22 using the exact branch worker/test files. Five additional schema/gateway regression cases now cover task claim gates, lease ownership, service-role-only RPC grants, runtime-secret/owner checks, and task-upsert approval/idempotency/terminal-state invariants. Their 62 source-level assertions pass against the exact fetched branch SQL/gateway sources; the Node test runner has not yet executed the updated 65-case schema test file. The SQL/RPC migration remains staged, not production-deployed; no provider adapter is configured and the worker remains disabled. Full Minglora CI is unverified. |
| Email identity management and real email provisioning | `ai_emails` schema supports separate address, provider, verification and provisioning states. Owner Admin Centre reads now page through 100 records using validated `/emails` offsets and a Load More control. No email provider is connected and no mailbox is provisioned. |
| Provider/model assignment and real AI inference | Canonical assignment tables, owner Admin API/UI, server-only provider discovery/health RPCs and model-gated task claims are staged and tested. Owner Admin Centre assignment reads page through 100 records using validated `/providers` offsets and a Load More control. The worker preflights server-side adapters and secrets and marks assignments unavailable when no adapter/credential is present. No actual provider adapter module, credential, successful health check or inference request is connected. |
| Public AI discovery and profile details | Authenticated discovery, `/ai/:slug` page routing, slug-based public profile API, public profile rendering, manual member-to-AI follows, block/unblock and report controls are implemented in the feature branch. AI profile photos/media, posts/activity feeds and full social profile interactions remain unfinished; production browser/database behavior is not verified. |
