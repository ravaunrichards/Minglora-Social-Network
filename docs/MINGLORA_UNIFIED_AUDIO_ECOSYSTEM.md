# Minglora Unified Audio Ecosystem — Foundation

## Status

This is the first additive foundation for a shared platform-wide audio system. It does not claim that the full ecosystem is complete. Existing ringtone, notification, creator-sound, post, Story, voice-note, call and LIVE implementations remain in place while integration is staged.

## Existing functionality retained

- Account-level call ringtones and 22 notification preference categories.
- The creator-owned sound library and its private uploads.
- Existing post and Story soundtrack metadata and playback.
- Existing audio attachments, call and LIVE audio flows.
- Existing private Supabase buckets `minglora-sounds` and `minglora-ringtones`.

No existing audio files, preferences, media records or assignments are deleted or rewritten by this foundation migration.

## Central registry

`backend/modules/sounds/registry.js` owns canonical category and event keys plus validation shared by API, admin and tests. Integrations should resolve event keys through the registry rather than scattering audio file paths or event-to-file mappings across features.

Platform event keys are stable API identifiers. The registry includes a disabled Marketplace order event because Marketplace is retired in the current runtime; it is not enabled or restored by the audio foundation.

## Authentic-recording and licence gate

A platform asset must have an original source page, a named licence and licence URL, a recorded download date, a SHA-256 checksum, validated audio metadata, a verified-authentic recording review, explicit commercial-use permission, explicit redistribution permission, and required attribution text. AI-generated speech, robotic voices, procedural audio, oscillator tones and synthesized sound effects are not accepted as authentic recordings.

The legacy 120 WAV cues were generated by the old procedural sound-pack script. They are compatibility assets only, not authentic recordings; they are not grandfathered into this catalogue and should not be labelled or counted as verified recordings. They are not removed by this migration because existing call and notification preferences may refer to them. The current Sound Studio no longer offers those generated cues for new selection, preview or offline caching, and the platform event engine does not use them. The original files and stored preference identifiers are retained for compatibility, not considered approved assets, and should be replaced only with real licensed recordings.

A file being free to download is not proof of commercial-use or redistribution permission. Every asset is reviewed individually; source lists are discovery references, not blanket licences.

## Database foundation

The additive migration introduces relational tables for categories, sources, licences, event definitions, registered assets, asset versions, sound profiles, event assignments, member preferences, favourites, multitrack projects and tracks, usage, reports and audit history. All new tables have RLS enabled and direct `anon`/`authenticated` grants revoked. Access must go through authenticated server-side operations using the service role; never place a service-role key in browser or mobile code.

The migration does not change existing storage bucket visibility, existing storage policies, auth, media ownership records, or runtime-state records.

## Current limits

The owner/MFA Admin Sound Management Centre, private upload/preview/review/assignment API, stored-binary SHA-256 verification and five-minute signed playback resolver have now been added on the feature branch. A shared browser audio engine is integrated with newly detected notification alerts and call ringtone lookup; oscillator-generated Messenger, call ringback and LIVE speaker-request tones were removed. The Supabase schema is applied, but the Edge Function and Render application code have not been deployed. Remaining work includes complete event adapters, category/profile management, user multitrack editing and rendering, discovery, creator audio, mobile/device adapters and device validation. The current feature-branch CI passed repository structure, JavaScript syntax, the full 957-test suite, Auth/OAuth acceptance and For You navigation. Real recordings and supported-device validation remain outstanding.

## Required import record

For each candidate asset, preserve: original filename, source website and exact download page, format, description, licence and licence URL, attribution, commercial-use permission, redistribution permission, download date, SHA-256, duration, sample rate, bitrate, channels and file size. An asset must not be marked approved until the exact binary file is present and checksum-verified.

## Safe rollout

1. Apply this additive relational migration in a reviewed Supabase deployment.
2. Integrate the server-side catalogue API and owner/MFA-protected Admin Centre.
3. Implement official-asset upload, inspection, licensing review, approval and signed delivery.
4. Replace legacy procedural cues only after a real recording is sourced, verified and assigned.
5. Integrate each existing platform event without altering established user preferences.
6. Implement user multitrack editing and render/export infrastructure.
7. Run repository CI, Supabase security/performance advisors, integration tests and supported-device tests before calling any stage complete.
